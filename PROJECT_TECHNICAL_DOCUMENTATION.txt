9. `chats` & `messages` (Chat.js, Message.js): Real-time chat threads and attachment messages.
10. `dailyreports` (DailyReport.js): End-of-day work summaries submitted by employees.
11. `screenshots` (Screenshot.js): Time-stamped screen captures taken by the Desktop Tracker.
12. `payrolls` (Payroll.js): Monthly salary breakdown, deductions, and payslip data.
13. `events` & `holidays` (Event.js, Holiday.js): Calendar announcements and official company holidays.
14. `notifications` (Notification.js): Real-time user alert records.
15. `auditlogs` (AuditLog.js): Security and administrative action history log.
16. `departments`, `roles`, `teams`, `projects` (Department.js, Role.js, Team.js, Project.js): Organizational structure definitions.
17. `compoffrequests` (CompOffRequest.js): Compensatory leave credit claims.
18. `ondutyrequests` (OnDutyRequest.js): Fieldwork / On-duty attendance exception applications.

9. AUTHENTICATION & SECURITY SYSTEM
--------------------------------------------------------------------------------
Authentication Architecture: JWT (JSON Web Token) Stateless Authentication
Header Format: `Authorization: Bearer <JWT_TOKEN>`
Password Encryption: Salted Bcrypt hashing (`bcryptjs` with 10 rounds).

Login Workflow:
1. User enters email and password at gateway (`/login`).
2. Frontend posts payload to `/api/auth/login`.
3. Backend validates email against `User` collection and executes `bcrypt.compare()`.
4. Upon success, backend signs a compact JWT token (containing `{ id, role, name, email }`).
5. Frontend stores token in `sessionStorage` and sets global Axios header.
6. Axios request interceptor (`frontend/shared/services/api.js`) automatically attaches `Bearer <token>` to all subsequent HTTP requests.
7. Backend `protect` middleware (`authMiddleware.js`) verifies token signature and populates `req.user`.

20. SECURITY AUDIT & HARDENING MEASURES
--------------------------------------------------------------------------------
Verified Security Implementations:
1. Password Security: Salted Bcrypt hashing (10 rounds) in `User.js` pre-save hook.
2. Lightweight JWT Payloads: JWT payload contains minimal user identity (`id`, `role`, `name`, `email`) preventing HTTP header size overflow (`400/431` errors).
3. CORS Policy: Configured in `backend/index.js` with credentials support.
4. Compression & Caching: Gzip payload compression via `compression` middleware and explicit `no-cache` response headers on SPA `index.html` entries.
5. Error Protection: Global `uncaughtException` and `unhandledRejection` process listeners in `backend/index.js` preventing server downtime.
6. DNS Resolver Fallback: Explicit Google/Cloudflare DNS resolver configuration (`dns.setServers(['8.8.8.8', '1.1.1.1'])`) preventing SRV connection drops.

26. IMPORTANT BUSINESS LOGIC RULES
--------------------------------------------------------------------------------
1. Attendance Calculation Rule:
   - Standard working hours >= 7.5 hours is status `Present`.
   - Working hours < 7.5 hours is status `Half Day`.
   - Status `Late` is deprecated across the entire platform in favor of simplified Present / Half Day / Leave / Absent tracking.
2. Multi-Role Navigation Rule:
   - Users are automatically routed to their designated primary workspace based on JWT role (`/admin`, `/hr`, `/manager`, `/employee`).
3. Master Personnel Synchronization:
   - Creating a user in `User` collection automatically synchronizes and creates a corresponding record in `Employee` collection.
